## Summary
Verified and completed issue #170: Observatory first-run play loop with observe→inspect→intervene→evaluate objectives. Implemented persistent state management using localStorage so players can resume mid-flow across page reloads, with contextual prompts, auto-pause at meaningful moments, and deterministic progression logic.

## Implementation Details

### Core Observatory System
- **State Machine** (src/ui/observatoryObjectives.ts): 4-step objective progression (observe→inspect→intervene→evaluate) with completion tracking, skip support, and onboarding flag management
- **Contextual UI** (src/ui/ObservatoryGuide.tsx): Renders active objective title/description/hint; auto-marks objectives complete when conditions met (observation after 50+ ticks, inspection on tile/species selection, intervention on world modification, evaluation 20+ ticks after intervention)
- **Onboarding Integration** (src/ui/FirstRunOnboarding.tsx): Welcome dialog gates on legacy flag; marks `isOnboarded=true` in both localStorage and Zustand store when dismissed

### Persistence (Karen's Gap #1)
- **Loading**: `loadObservatoryState()` called in App.tsx:471 during world initialization (`useEffect` on mount) to hydrate store with saved objectives/completion state
- **Saving**: `saveObservatoryState()` called after each objective progression change (ObservatoryGuide.tsx lines 35,50,72,94,118; FirstRunOnboarding.tsx lines 42,47)
- **LocalStorage Key**: `origins_observatory_state` persists entire ObservatoryState object including isOnboarded, objectives[], currentObjective, completion ticks
- **Resumption**: On reload, guide re-renders with preserved `isOnboarded=true` and `currentObjective` set to next incomplete objective; player can continue where they left off

### Auto-Pause Feature
- **Trigger Logic** (observatoryObjectives.ts:190-212): Pauses at first creature spawn, >20% population delta, and early deaths (≤5 total)
- **Integration** (App.tsx:172-198): Wired into publish callback; checks observatoryState.isOnboarded && currentObjective before pausing to avoid unwanted pauses after guide completion

### Non-Blocking UI
- **CSS** (src/styles/observatory-guide.css): Fixed position bottom-left with collapsible toggle; mobile breakpoints (@640px, @700px height) reposition to avoid overlap with controls
- **Render Conditions** (ObservatoryGuide.tsx:99-105): Returns null if observatoryState is null, not onboarded, all completed, or no current objective; never blocks world view or simulation controls
