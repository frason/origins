# Worker output — issue #276 (adaptation-evidence labeling, evolution truth)

## What landed
New evidence-threshold classifier `src/simulation/adaptationEvidence.ts` plus
cohort wiring in `AdaptationMetricsTracker`. Labels a lineage's trait trend as
one of: drift, mutation-appearance, selection, speciation — ONLY when a
documented threshold in `DEFAULT_ADAPTATION_THRESHOLDS` is crossed; anything
else is `insufficient-evidence` (never a guess).

## How evidence is gathered (no guesswork)
- At each window boundary the tracker captures the alive cohort (traits +
  cumulative offspringCount per member).
- At the next boundary it resolves real outcomes per member: survived =
  still alive; offspring delta from the counters (corpses still carry finals).
- Classification correlates trait values against those outcomes:
  - selection: |point-biserial r| >= 0.35 in 2 of last 3 windows AND a
    directional mean shift >= 2% agreeing with the correlation's sign.
  - drift: shift >= 2% with NO fitness correlation in any recent window.
  - mutation-appearance: discrete value never seen before at >= 5% frequency;
    continuous value jumping beyond the prior range by >= 50% of its width at
    >= 10% frequency (a ratcheting max from selection/drift does not qualify).
  - speciation: divergence from the lineage's own baseline >= 35% for 3
    consecutive windows on >= 2 traits at once (multi-trait signature).
- Every verdict carries greppable reasons naming the thresholds used;
  `insufficient-evidence` maps to legacy changeType `unknown`.
