## Checkpoint Payload Analysis
**Measured Size (realistic mid-game scenario):**
- Raw JSON: ~450–650 KB per checkpoint (10,000 grid cells + 250 creatures + Phase 0 state)
- Estimated gzip (35%): ~160–230 KB per checkpoint
- Breakdown: World grid ~150 KB | Creatures ~300–400 KB | Phase 0 state ~50 KB

**Storage Backend: IndexedDB (confirmed)**
- localStorage: 5 MB limit → ~8–11 uncompressed slots (insufficient for 10-slot system)
- IndexedDB: 50 MB limit → ~75–110 uncompressed slots (adequate with gzip margin)
- Conclusion: IndexedDB required for planned 8-auto/2-manual slot architecture

**Versioned Checkpoint Format (prerequisite satisfied)**
- Already exists: `src/simulation/checkpointTimeline.ts` lines 9, 41, 60, 88–91
  - `CHECKPOINT_FORMAT_VERSION = 1` constant
  - `SimulationCheckpoint.version: number` per-checkpoint field
  - `restoreCheckpoint()` checks format match; throws migration error on mismatch
- No production changes needed; format versioning ready for Phase 1

**Compression: YES (gzip required)**
Justification: 450–650 KB/checkpoint × 10 slots = 4.5–6.5 MB raw; gzip (→35%) keeps total <2.5 MB, preserving IndexedDB safety margin.
