Issue #274 — Living World: wire the 2D map fallback toggle
Status: COMPLETE (code + tests)

Problem
`show2dView`/`setShow2dView` existed in src/state/store.ts with zero consumers,
and App.tsx mounted BOTH `<LiveThreeWorldView />` and `<WorldView />`
unconditionally (App.tsx:636-637). Both compute height:100% inside an
overflow:hidden shell, so the 2D view was always invisible under the 3D one.
The two views also both emitted id="world-keyboard-instructions" (duplicate id).

Change
- src/App.tsx
  - Subscribe to show2dView / setShow2dView.
  - Add a toggle button in the transport bar: data-testid="toggle-view-button",
    aria-pressed, aria-label="Toggle between 3D and 2D map view (press M)".
  - Add an "M" keyboard shortcut (window keydown) with guards for
    ctrl/meta/alt/shift and for INPUT/TEXTAREA/SELECT/contentEditable focus.
  - Swap to exclusive mounting: {!show2dView && <LiveThreeWorldView />} and
    {show2dView && <WorldView />} — one view in the DOM at a time, so the CSS
    clipping concern is moot and the duplicate id is gone.
- src/ui/LiveThreeWorldView.tsx — add data-testid="live-three-world-view" to
  both the loading and loaded roots.
- src/ui/WorldView.tsx — add data-testid="world-view" to the root.
- src/tests/viewToggle.test.tsx (new, 6 tests) — default 3D-only render,
  2D-only render, click swap both directions, "M" toggles, modifier keys
  suppressed, form-field focus suppressed.
- src/tests/appAccessibility.test.tsx — previously asserted the 2D canvas's
  a11y attributes, which only held because both views were always mounted.
  Rewritten to assert the shell landmarks in either mode and the 2D canvas
  contract with show2dView enabled.
