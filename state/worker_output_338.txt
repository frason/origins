## Summary
Verified the fix for false-negative in dispatcher.sh's worker-hallucination check. The implementation correctly captures pre-run HEAD state before worker invocation and includes commits made during the run in the hallucination detection logic, allowing workers that correctly `git commit` their claimed files mid-run to be properly recognized instead of flagged as hallucinating.

## Changes
The fix is already implemented in scripts/dispatcher.sh with two key additions:

1. **Capture pre-run HEAD (line 1106)**: Right after output_file reset and before the worker prompt is created:
   ```bash
   pre_run_head=$(git rev-parse HEAD 2>/dev/null || true)
   ```
   This captures the git HEAD state before the worker runs, serving as a baseline for detecting commits made during execution.

2. **Include committed changes in hallucination check (lines 1215-1218)**: The `git_changes` collection was extended to include files changed in commits made since pre_run_head:
   ```bash
   # Also include files changed in commits made during this run (guard for empty pre_run_head)
   if [ -n "$pre_run_head" ]; then
     git diff --name-only "$pre_run_head" HEAD 2>/dev/null || true
   fi
   ```
   This is guarded by a check for non-empty `$pre_run_head` to safely handle edge cases (e.g., first commit ever in the repo).

The fix is additive: existing `git diff --name-only HEAD` and `git status --short` checks remain unchanged. Only the "claimed files not found in git changes" branch's input was extended; the other two hallucination branches (missing output file, missing manifest line) remain unmodified as specified.
