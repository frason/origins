## Summary
Fixed false-negative in dispatcher.sh's worker-hallucination check by capturing pre-run HEAD and including committed changes in the git_changes collection. Workers that correctly `git commit` their claimed files mid-run are no longer incorrectly flagged as hallucinating.

## Changes
The fix implements two key changes to scripts/dispatcher.sh:

1. **Capture pre-run HEAD (line 1106)**: Before invoking the worker, capture the current HEAD commit:
   ```bash
   pre_run_head=$(git rev-parse HEAD 2>/dev/null || true)
   ```
   This baseline allows detecting commits made during the worker's execution.

2. **Include committed changes in hallucination check (lines 1212-1219)**: Extended the `git_changes` collection to also check commits made between pre-run and current HEAD:
   ```bash
   git_changes=$(
     git diff --name-only HEAD 2>/dev/null || true
     git status --short 2>/dev/null | sed 's/^[A-Z? ][A-Z? ] //' || true
     # Also include files changed in commits made during this run (guard for empty pre_run_head)
     if [ -n "$pre_run_head" ]; then
       git diff --name-only "$pre_run_head" HEAD 2>/dev/null || true
     fi
   )
   ```

The fix guards against empty `$pre_run_head` (edge case of first commit ever) to avoid command errors.
